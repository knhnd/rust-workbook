## Q1 シャドーイングとスコープ

### 正解

```
inner: 12
outer: 6
```

### 解説

`let` を書くたびに、同じ名前の**新しい変数**が作られます。古い変数の値を上書きしているわけではありません。新しい変数が古い変数を「影に隠す」ので、これを**シャドーイング**と呼びます。

```rust
let x = 5;          // ① x（1代目）= 5
let x = x + 1;      // ② 1代目を読んで、x（2代目）= 6 を新しく作る
{
    let x = x * 2;  // ③ ブロックの中だけで生きる x（3代目）= 12
    println!("inner: {x}");   // → 12
}                   // ④ ブロックが終わると3代目は消える
println!("outer: {x}");       // → 隠れていた2代目が再び見える → 6
```

### よくある間違い

- **TS経験者**：「同じ名前の変数を2回宣言しているからエラーになる」と考えがちです。TSでは同じスコープでの `let` の再宣言はエラーですが、Rustでは許されています。
- **Python経験者**：`outer: 12` と予想しがちです。Pythonの `if` や `for` にはスコープがないので、ブロック内の代入が外側の変数を上書きします。Rustの `{ }` は独立したスコープなので、外側には影響しません。

## Q1' シャドーイングと `mut` の違い

### 正解

**(a)** コンパイルエラーになります。

```
error[E0384]: cannot assign twice to immutable variable `x`
```

**(b)** コンパイルが通り、`inner: 12`、`outer: 12` になります。

### 解説

ルールは次の2つだけです。

1. **`let` あり**：新しい変数を作る（シャドーイング）
2. **`let` なし**：今見えている一番新しい変数に代入する（その変数が `mut` でなければエラー）

一度シャドーイングされた古い変数には、二度とアクセスできません。名前 `x` は、常に「今見えている一番新しい `x`」を指します。

**(a)** では、`let` がないので新しい変数は作られず、2代目の `x` に代入しようとします。2代目は `mut` なしで作られているので変更できず、エラーになります。

**(b)** では、2代目が `mut` 付きで作られているので代入できます。新しい変数は作られず、2代目そのものが 12 に書き換わります。そのため、ブロックを抜けても 12 のままです。Q1で `outer` が 6 に戻ったのとは対照的です。

### よくある間違い

- **`mut` の意味を逆に覚える**：`mut` は mutable（変更**可能**）の略です。Rustは何も付けないと変更不可で、変更したいときだけ `mut` を付けます。
- **(b) で 10 と答える**：1代目の `x`（5）が書き換わると考えると、こうなります。シャドーイングされた1代目には、もうアクセスできません。

## まとめ：なぜシャドーイングがあるのか

### シャドーイングと `mut` の違い

| | シャドーイング（`let` で再宣言） | `mut` で再代入 |
|---|---|---|
| 正体 | **新しい変数**を作る | **同じ変数**の値を書き換える |
| 型の変更 | できる | できない |
| 変更後の状態 | 変更不可のまま | ずっと変更可能 |
| ブロックを抜けると | 元の変数に戻る | 書き換えたまま |

### シャドーイングの使いどころ

**① 型を変えたいけれど、名前は変えたくないとき**

```rust
let guess = String::from("42");
let guess: u32 = guess.trim().parse().expect("数字ではありません");
```

「ユーザーの予想」という同じ概念を、文字列から数値に変換しています。TSなら `guessStr` と `guessNum` のように別の名前が必要ですが、Rustでは同じ名前のまま、型チェックも効かせられます。

**② 加工が終わったら、値を固定したいとき**

```rust
let data = "  Hello World  ";
let data = data.trim();
let data = data.to_lowercase();
// ここ以降、data は変更できない
```

`let mut data` で書くと、加工が終わったあともずっと変更可能なままです。シャドーイングなら、加工が終わった時点で値が確定したことがコードから読み取れます。

**③ 一時的な変更をブロック内に閉じ込めたいとき**

Q1のように、ブロックの中だけで値を変えて、ブロックを抜けたら元に戻せます。

> [!TIP]
> シャドーイングは便利ですが、まったく別の意味の値に同じ名前を使い回すと、かえって読みにくくなります。「同じ概念の変換」に使うのが良い作法です。

### `mut` は悪者ではない

`mut` は TS の `any` のような「逃げ道」ではありません。`mut` を付けてもコンパイラのチェックはすべて効いたままです。TSの `let` と `const` の使い分けと同じで、**まず `mut` なしで書き、変更が必要になったら付ける**のが基本です。不要な `mut` を付けると、コンパイラが警告で教えてくれます。
