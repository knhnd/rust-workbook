## Q1 シャドーイングとスコープ

### 正解

```
inner: 12
outer: 6
```

### 解説

`let` を書くたびに、同じ名前の**新しい変数**が作られる。古い変数の値を上書きしているわけではない。新しい変数が古い変数を「影に隠す」ので、これを**シャドーイング**と呼ぶ。

```rust
let x = 5;          // ① x（1代目）= 5
let x = x + 1;      // ② 1代目を読んで、x（2代目）= 6 を新しく作る
{
    let x = x * 2;  // ③ ブロックの中だけで生きる x（3代目）= 12
    println!("inner: {x}");   // → 12
}                   // ④ ブロックが終わると3代目は消える
println!("outer: {x}");       // → 隠れていた2代目が再び見える → 6
```

### よくある間違い

- **TS経験者**：「同じ名前の変数を2回宣言しているからエラーになる」と考えがち。TSでは同じスコープでの `let` の再宣言はエラーだが、Rustでは許されている。
- **Python経験者**：`outer: 12` と予想しがち。Pythonの `if` や `for` にはスコープがないので、ブロック内の代入が外側の変数を上書きする。Rustの `{ }` は独立したスコープなので、外側には影響しない。

## Q1' シャドーイングと `mut` の違い

### 正解

**(a)** コンパイルエラー。

```
error[E0384]: cannot assign twice to immutable variable `x`
```

**(b)** コンパイルが通り、`inner: 12`、`outer: 12`。

### 解説

ルールは次の2つだけ。

1. **`let` あり**：新しい変数を作る（シャドーイング）
2. **`let` なし**：今見えている一番新しい変数に代入する（その変数が `mut` でなければエラー）

一度シャドーイングされた古い変数には、二度とアクセスできない。名前 `x` は、常に「今見えている一番新しい `x`」を指す。

**(a)** では、`let` がないので新しい変数は作られず、2代目の `x` に代入しようとする。2代目は `mut` なしで作られているので変更できず、エラーになる。

**(b)** では、2代目が `mut` 付きで作られているので代入できる。新しい変数は作られず、2代目そのものが 12 に書き換わる。そのため、ブロックを抜けても 12 のまま。Q1で `outer` が 6 に戻ったのとは対照的。

### よくある間違い

- **`mut` の意味を逆に覚える**：`mut` は mutable（変更**可能**）の略。Rustは何も付けないと変更不可で、変更したいときだけ `mut` を付ける。
- **(b) で 10 と答える**：1代目の `x`（5）が書き換わると考えるとこうなる。シャドーイングされた1代目には、もうアクセスできない。

## まとめ：なぜシャドーイングがあるのか

### シャドーイングと `mut` の違い

| | シャドーイング（`let` で再宣言） | `mut` で再代入 |
|---|---|---|
| 正体 | **新しい変数**を作る | **同じ変数**の値を書き換える |
| 型の変更 | できる | できない |
| 変更後の状態 | 変更不可のまま | ずっと変更可能 |
| ブロックを抜けると | 元の変数に戻る | 書き換えたまま |

### シャドーイングの使いどころ

**① 型を変えたいけれど、名前は変えたくないとき**

```rust
let guess = String::from("42");
let guess: u32 = guess.trim().parse().expect("数字ではありません");
```

「ユーザーの予想」という同じ概念を、文字列から数値に変換している。TSなら `guessStr` と `guessNum` のように別の名前が必要だが、Rustでは同じ名前のまま、型チェックも効かせられる。

**② 加工が終わったら、値を固定したいとき**

```rust
let data = "  Hello World  ";
let data = data.trim();
let data = data.to_lowercase();
// ここ以降、data は変更できない
```

`let mut data` で書くと、加工が終わったあともずっと変更可能なまま。シャドーイングなら、加工が終わった時点で値が確定したことがコードから読み取れる。

**③ 一時的な変更をブロック内に閉じ込めたいとき**

Q1のように、ブロックの中だけで値を変えて、ブロックを抜けたら元に戻せる。

> [!TIP]
> シャドーイングは便利だが、まったく別の意味の値に同じ名前を使い回すと、かえって読みにくくなる。「同じ概念の変換」に使うのが良い作法。

### `mut` は悪者ではない

`mut` は TS の `any` のような「逃げ道」ではない。`mut` を付けてもコンパイラのチェックはすべて効いたまま。TSの `let` と `const` の使い分けと同じで、**まず `mut` なしで書き、変更が必要になったら付ける**のが基本。不要な `mut` を付けると、コンパイラが警告で教えてくれる。

## Q2 不変性と型

### 正解

```rust
let mut count = 0;          // ① mut を付ける
count += 1;

let spaces = "   ";         // ② mut を外し、
let spaces = spaces.len();  //    シャドーイングで型を変える
```

解答例：[examples/q2_mutability.rs](./examples/q2_mutability.rs)

### 解説

**1つ目のエラー（最初に表示される）：型が合わない**

```
error[E0308]: mismatched types
8 |     let mut spaces = "   ";
  |                      ----- expected due to this value
9 |     spaces = spaces.len();
  |              ^^^^^^^^^^^^ expected `&str`, found `usize`
```

`spaces` は8行目で文字列（`&str`）を入れた時点で型が決まる。9行目では、そこに長さ（`usize` という数値）を入れようとしている。**`mut` で変えられるのは値だけで、型は変えられない。**

Pythonでは**値**が型を持つので、変数に別の型の値を入れ直せる。Rustでは**変数**が型を持つので、それができない。型を変えたいときは、シャドーイングで新しい変数を作る。シャドーイングに切り替えると `mut` が不要になり、コンパイラが「この `mut` はいらない」と警告してくれる。

**2つ目のエラー（1つ目を直すと現れる）：不変の変数への再代入**

```
error[E0384]: cannot assign twice to immutable variable `count`
```

`count` は `mut` なしで作られているので、`+= 1` で書き換えられない。`let count = count + 1;` とシャドーイングでも通るが、カウンタは「同じ変数の値を更新する」ものなので、`mut` を付けるのが自然。

**考察：なぜエラーが2つ同時に出なかったのか**

Rustのコンパイラは、チェックを段階的に進める。

```
構文チェック → 型チェック → 借用チェック（mut の有無などを確認）→ …
```

同じ段階のエラーはまとめて表示されるが、前の段階でエラーがあると次の段階に進まない。`spaces` の型エラーは「型チェック」、`count` の再代入エラーは次の「借用チェック」で見つかるので、型エラーを直すまで表示されなかった。

### よくある間違い

- **「空文字列の `len()` がエラーになる」と読む**：`"   "` はスペース3つの文字列で、`len()` は `3` を返す。問題は `len()` ではなく、数値を文字列型の変数に入れようとしていること。エラーメッセージの矢印（`expected due to this value` と `expected &str, found usize`）を順に読むと原因がわかる。

### 補足：型の書き方

変数の型は基本的に推論に任せて省略する。書くこともできる。

```rust
let a: u32 = 5;
```

| 場所 | 型注釈 |
|---|---|
| 変数（`let`） | 基本は省略。推論できないときだけ書く |
| 関数の引数・戻り値 | **必須**（TSと違って省略できない） |
| 定数（`const`） | **必須** |

なお、`let a: String = "Hello";` はエラーになる。文字列リテラルの型は `&str` で、`String` とは別の型。この2つの違いは ch02（所有権）で扱う。

## Q3 式と文

### 正解

`x + 1;` のセミコロンを削除する。

```rust
fn plus_one(x: i32) -> i32 {
    x + 1
}
```

解答例：[examples/q3_expressions.rs](./examples/q3_expressions.rs)

### 解説

```
1 | fn plus_one(x: i32) -> i32 {
  |    --------            ^^^ expected `i32`, found `()`
  |    implicitly returns `()` as its body has no tail or `return` expression
2 |     x + 1;
  |          - help: remove this semicolon to return this value
```

| | 意味 | 例 |
|---|---|---|
| **式** | 値を生み出す | `x + 1`、`5`、`plus_one(5)`、`{ ... }`、`if ... { } else { }` |
| **文** | 実行するだけで、値を生まない | `let y = 6;`、`x + 1;` |

**セミコロンは「式の値を捨てて文にする」記号。** そして、ブロック `{ }` の値は「**最後にある、セミコロンのない式**」になる。関数の本体もブロックなので、最後の式がそのまま戻り値になる。最後が文だと、ブロックの値は `()`（ユニット型。Pythonの `None`、TSの `void` に近い「何もない値」）になる。

### `return` を書かない理由

`return x + 1;` でも動くが、Rustでは最後の式で返すのが慣習。理由は3つ。

1. **一貫性**：関数の本体も「ただのブロック」なので、「ブロックの最後の式が値になる」という1つのルールで説明できる。Rustは OCaml や Haskell などの関数型言語の影響を受けた**式指向**の言語。
2. **不変性と相性が良い**：`if` やブロックが値を返せるので、`mut` なしで変数を初期化できる。
   ```rust
   let grade = if score >= 60 { "合格" } else { "不合格" };
   ```
3. **`return` を特別な合図にできる**：`return` は「途中で抜ける（早期リターン）」ときだけ使う、という目印になる。公式のチェックツール Clippy も、関数の最後の不要な `return` に警告を出す。

### `if` で値を返すときの注意

`else` のない `if` の値は、必ず `()` になる。また、関数の途中にある式の値は捨てられる。そのため、次の書き方はエラーになる。

```rust
fn fib(n: u32) -> u64 {
    if n <= 1 {
        n.into()      // ❌ else がなく、関数の途中にあるので戻り値にならない
    }
    // ...
}
```

| 書き方 | 使いどころ |
|---|---|
| `if 条件 { return 値; }` | 特殊なケースを先に処理して、途中で抜ける（早期リターン） |
| `if 条件 { 値1 } else { 値2 }` を関数の**最後**に置く | 2つのケースを対等に扱い、どちらかを返す |

## Q3' ブロックの値

### 正解

`y` の値は `()`。

### 解説

ブロックの最後の行 `a * 2;` が文（セミコロン付き）なので、ブロックの値は `()` になる。実際、コンパイラは「計算結果を使わずに捨てている」と警告を出す。`y` を表示するには `println!("{y:?}")` と書く（`{:?}` については Q4 の補足を参照）。

## Q4 フィボナッチ数と整数オーバーフロー

### 正解

解答例：[examples/q4_fibonacci.rs](./examples/q4_fibonacci.rs)

```rust
fn fib(n: u32) -> u64 {
    let mut a = 0;
    let mut b = 1;
    for _ in 0..n {
        (a, b) = (b, a + b);
    }
    a
}
```

### 手順1：`todo!()` の正体

```
    Finished `dev` profile ...           ← コンパイルは成功
     Running `target/debug/q4_fibonacci`
thread 'main' panicked at ...            ← 実行中に停止
not yet implemented: ここを実装してください（n = 10）
```

`todo!()` は「中身はまだないが、型チェックは通す」ための仮置き。実行すると **panic**（続行できないときの緊急停止）する。

| | タイミング | 例 |
|---|---|---|
| コンパイルエラー | 実行する前 | Q2・Q3 |
| panic | 実行している最中 | `todo!()`、オーバーフロー（debug時）、配列の範囲外アクセス |

Pythonの例外と違い、panicは基本的にキャッチして回復するものではない。回復できるエラーは `Result` 型で扱う（ch05）。

### 手順2：ループで実装する

Rustのループは `for`・`while`・`loop` の3種類。**第一選択は `for`**（インデックス管理が不要で、範囲外アクセスのバグが起きない）。

```rust
for i in 0..5 { }    // 0〜4（Pythonの range(5)）
for i in 0..=5 { }   // 0〜5
for _ in 0..n { }    // ループ変数を使わないときは _
```

ループ中は、常に `a = fib(k)`、`b = fib(k+1)` の関係が保たれる。n 回まわした後の `a` が `fib(n)`。`n = 0, 1` も正しく計算できるので、`if` による特別扱いは不要。

戻り値の型が `u64` で最後に `a` を返しているので、コンパイラは `a` と `b` を `u64` と推論する（**後ろのコードから逆算して型が決まる**）。

#### よくある間違い

- **Python風のタプル代入**：`a, b = b, a + b;` は構文エラー。Rustでは `(a, b) = (b, a + b);` と両辺をカッコで囲む。このときコンパイラの `help` は「`=` を `:` に変えて」と見当違いの提案をする。構文チェックの段階では、コンパイラもこちらの意図を読み違えることがある。**`help` は「ヒント」であって「正解」ではない。**
- **初期値の誤り**：`a = 0, b = 0` だと何回足しても `0`。
- **整数型の自動変換を期待する**：`fn fib(n: u32) -> u64` の中で `return n;` と書くとエラー。Rustは `u32` → `u64` のような変換も自動では行わない。`n.into()`（安全な変換）か `n as u64`（キャスト。小さい型へ変換すると値が切り捨てられることも）で変換する。迷ったら `into()`。
- **1つずれる**：`b` を返すと `fib(n+1)` になり、`fib(10)` が `89` になる。トレース表（ループごとの変数の値を書き出した表）を作ると原因がわかる。

| ループ回数 | `a` | `b` |
|---|---|---|
| 開始前 | 0 | 1 |
| 1回目のあと | 1 | 1 |
| 2回目のあと | 1 | 2 |
| 3回目のあと | 2 | 3 |

### 手順3：debug と release の違い

| | debug（`cargo run`） | release（`--release`） |
|---|---|---|
| 出力 | `attempt to add with overflow` で panic | `fib(100) = 3736710778780434371` |

**release は「動いた」のではなく、間違った値を黙って返している。** 正しい `fib(100)` は `354224848179261915075`（21桁）。release の出力は、正しい値を 2⁶⁴ で割った余り（上限を超えると0に戻る**ラップアラウンド**）。

| | debug | release |
|---|---|---|
| 最適化 | なし（ビルドが速い） | 全力（実行が速い） |
| オーバーフロー | panic | ラップアラウンド |
| メモリ安全性・型チェック | 効く | 同じく効く |
| 用途 | 開発中 | 本番・性能測定 |

Rustの立場は「オーバーフローはバグ」。開発中は panic で気づかせる。ただし、オーバーフローが起きるかは実行時の入力次第なので、テストで見つかるとは限らない。起こりうる箇所は、`checked_add` などで**コードとして明示的に**処理するのが基本。release でもチェックしたい場合は `Cargo.toml` で設定できる。

```toml
[profile.release]
overflow-checks = true
```

#### 整数型の種類

| 型 | 範囲 |
|---|---|
| `u8` | 0 〜 255 |
| `u32` | 0 〜 約42億 |
| `u64` | 0 〜 約1.8×10¹⁹ |
| `i32` | 約−21億 〜 約21億（**型を書かないときのデフォルト**） |
| `usize` | マシン依存（64ビット環境では `u64` と同じ）。長さや添字に使う |

`u` は符号なし、`i` は符号あり、数字はビット数。Pythonの `int` は桁数の上限がなく、TSの `number` は浮動小数点数。Rustはサイズの決まった型を自分で選ぶ（性能とメモリのため、そして「負にならない」などの意図を型で表すため）。`fib(100)` は約 3.5×10²⁰ で、`u64` の上限を超える。

### 手順4・5：`checked_fib`

```rust
fn checked_fib(n: u32) -> Option<u64> {
    if n == 0 {
        return Some(0);
    }
    let mut a: u64 = 0;
    let mut b: u64 = 1;
    for _ in 1..n {
        let sum = a.checked_add(b)?;
        (a, b) = (b, sum);
    }
    Some(b)
}
```

#### オーバーフロー時の挙動を選ぶメソッド

| メソッド | オーバーフローしたら |
|---|---|
| `checked_add` | `None` を返す |
| `wrapping_add` | ラップアラウンド（release の挙動を明示的に選ぶ） |
| `saturating_add` | 上限値で止まる |

#### `Option` と `match`

`Option<u64>` は「`u64` の値があるかもしれないし、ないかもしれない」箱。

- `Some(値)`：値が入っている
- `None`：値が入っていない

Pythonの `Optional[int]`、TSの `number | undefined` に近い。違いは、**箱から出さないと中身を使えない**こと。`None` の場合の処理を書かないとコンパイルが通らないので、null チェックの書き忘れを型で防げる。

箱を開けるには `match` を使う。

```rust
match a.checked_add(b) {
    Some(sum) => (a, b) = (b, sum),  // Some なら中身を sum として取り出す
    None => return None,             // None なら関数ごと抜ける
}
```

`Some(sum)` は「`Some` かどうかの確認」と「中身を `sum` という名前で取り出す」を同時に行う。`match` はすべての場合を書かないとエラーになる。

解答例の `let sum = a.checked_add(b)?;` は、この `match` と同じ意味。`?` は「`None` ならその場で `None` を返し、`Some` なら中身を取り出す」演算子。詳しくは ch03・ch05 で扱う。

#### 隠れたバグ：`checked_fib(93)` が `None` になる

手順2の `fib` と同じ形（`0..n` でループして `a` を返す）で書くと、`checked_fib(93)` が `None` になる。`fib(93)` は約1.2×10¹⁹ で `u64` に**収まる**のに。

ループ中は `a = fib(k)`、`b = fib(k+1)` なので、`sum = a + b` は `fib(k+2)`。最後のループ（`k = n-1`）では `fib(n+1)` を計算している。`n = 93` だと、答えに使わない `fib(94)`（`u64` に収まらない）を計算してオーバーフローしていた。

ループを `1..n`（1回少なく）にして `b` を返せば、余計な計算をしない。`n = 0` のときだけは早期リターンで先に処理する。

#### よくある間違い

- **メソッド呼び出しで型推論が効かない**：`let mut a = 0;` のまま `a.checked_add(b)` と書くと、「型があいまいな整数ではメソッドを呼べない」というエラーになる。`a + b` のような演算子と違い、メソッドは呼び出す時点で型が確定している必要がある。`let mut a: u64 = 0;` と型を書く（または `0u64`）。このときコンパイラの `help` は `i32` を提案するが、戻り値の `Option<u64>` と合わないので `u64` にする。

### 補足：`{}` と `{:?}`

```rust
let x = 10;
println!("x = {}", x);   // 後ろの引数を順に {} に入れる（Pythonの format）
println!("x = {x}");     // 変数名を直接書く（Pythonのf文字列。ただし式は書けない）
```

| Rust | 意味 | Pythonでいうと |
|---|---|---|
| `{}` | ユーザー向けの表示 | `str(x)` |
| `{:?}` | 開発者向けの表示（デバッグ表示） | `repr(x)` |

`Option` や `()` は、ユーザーにどう見せるかが一意に決まらないので、`{}` では表示できず、`{:?}` だけ使える。`{:.2}`（小数点以下2桁）、`{:>5}`（右寄せ）など、Pythonと似た表示指定もある。
